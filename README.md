# My Extension

A Raycast extension built from [raycast-extension-template](https://github.com/harunonsystem/raycast-extension-template).

## Requirements

- Raycast 2 or later on macOS
- Node.js 22.22.2 or later and npm
- A Raycast account for development and Store publishing

The repository pins the minimum supported Node version in `.nvmrc`, which CI also uses.

## Getting Started

1. Click **"Use this template"** on GitHub to create your repository
2. Clone your new repository
3. Install dependencies:
   ```bash
   npm ci
   ```
4. Update `package.json`:
   - `name`: Your extension's unique identifier
   - `title`: Display name in Raycast
   - `description`: What your extension does
   - `author`: Your Raycast Store username
   - `platforms`: Keep `macOS`, or add `Windows` after testing on Windows
   - `icon`: Replace `assets/command-icon.png` with your 512x512 PNG icon
5. Start developing:
   ```bash
   npm run dev
   ```

## Development

| Command            | Description                                                          |
| ------------------ | -------------------------------------------------------------------- |
| `npm run dev`      | Start development mode (opens in Raycast)                            |
| `npm run build`    | Type-check and build into `dist/`                                    |
| `npm run lint`     | Run ESLint checks                                                    |
| `npm run fix-lint` | Auto-fix ESLint issues                                               |
| `npm run publish`  | Validate and open a Store submission PR using the latest Raycast CLI |

`raycast-env.d.ts` is generated by the Raycast CLI and included in TypeScript checking. Do not edit or commit it. Node and React type versions follow the API package's exact peer dependencies. CI runs `npm run check-runtime-types` to reject mismatches, including nested peer installations that npm otherwise accepts. If a Renovate runtime update fails this check, align the two type versions with the API package's peer dependencies before merging. TypeScript stays on the newest major supported by `@raycast/eslint-config`.

## Dependency Updates

Renovate updates npm dependencies, the lockfile, the Node version, and GitHub Actions. All update types, including major updates, are eligible for squash automerge once required CI passes. New dependency releases wait three days before an update is proposed. Review behavioral changes that build and lint cannot detect.

For each repository created from this template:

1. Install or enable the [Renovate GitHub App](https://github.com/apps/renovate) for that repository.
2. Enable **Allow auto-merge** and **Allow squash merging** in GitHub repository settings.
3. Protect `main` with a required pull request and the `build-and-lint` status check. Do not require a human approval if unattended Renovate merging is intended.

GitHub App access and branch protection settings are not copied when creating a repository from a template. Without a required check, GitHub can merge an update before CI finishes.

## Publishing

Customize the manifest, sample command, icon, README, and changelog before submitting your extension. Run `npm run build` and `npm run lint`, then test the command in Raycast. Use `npm run publish` to open a pull request in `raycast/extensions`. Bare `npm publish` is blocked to prevent accidental npm registry publication.

Put Store screenshots in `metadata/`, README images in `media/`, and runtime assets in `assets/`. Add `help.md` only when required preferences need setup instructions. Add AI tools and their configuration only when your extension exposes functionality to Raycast AI.

## Raycast Store Submission Checklist

Before submitting a PR to the [raycast/extensions](https://github.com/raycast/extensions) repository:

- [ ] All user-facing text is in US English (no Japanese or other languages)
- [ ] `npm run build` succeeds without errors
- [ ] `npm run lint` passes without errors
- [ ] Extension icon is a 512x512 PNG file
- [ ] Screenshots are 2000x1250px (16:10 aspect ratio) and in English
- [ ] `package.json` has valid `author`, `categories`, and `license: "MIT"`
- [ ] CHANGELOG.md is updated with your changes
- [ ] README.md describes what the extension does and how to use it
- [ ] No empty files in the repository
- [ ] No references to non-existent files or commands in documentation
- [ ] `.prettierrc` is configured with `printWidth: 120` and `singleQuote: false`
